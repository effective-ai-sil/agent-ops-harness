# Memory index

Loaded at the start of every session. One line per memory; the detail lives in the linked file and is read only when relevant.

- [Owner prefers drafts, not sends](feedback-drafts-not-sends.md): every outbound message is a draft for the owner to review
- [Reporting week is Mon-Sun, NZ time](project-reporting-week.md): applies to all client reports
- [Verify by running, not reading](feedback-verify-by-running.md): "verified" means executed, rendered, queried or read back

Rules for memory:
- One fact per file, with a type: user | feedback | project | reference.
- Feedback and project memories carry **Why** and **How to apply**, so the rule can be judged in a new situation, not just obeyed.
- A path, name, config value or state recalled from memory is a claim. Check it before acting on it.
- Before adding a memory, update an existing one if it covers the same thing. Delete memories that turn out to be wrong.
